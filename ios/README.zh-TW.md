# Folia iOS 0.3.7 · build 15

以 [Folia Major](https://github.com/chthollyphile/folia-major/tree/3125d376557182e25a12c915e39099db13ba63c8) 為基礎的非官方 iPhone 移植。介面使用 SwiftUI，播放使用 AVFoundation，鎖定畫面與控制中心使用 MediaPlayer。iPhone 最低系統版本為 iOS 17。Xcode 會解析固定版本的 YouTubeKit 套件；Sonnet 的 JavaScript 與依賴已隨 App 離線打包。這版介面提供臺灣繁體中文。

## 第一版功能

- 從「檔案」匯入 iOS 可播放的音檔，例如 MP3、AAC、M4A、WAV，儲存於 App 的本機曲庫。
- 使用播放佇列、上一首、下一首、循環和拖曳進度。音訊工作階段配置背景播放，並接上鎖定畫面和控制中心的播放指令。
- 顯示 LRC、逐字 Enhanced LRC、Folia 匯出的 `.fia`。也會讀取系統能辨識的內嵌 LRC。從「檔案」選取同名音檔和歌詞可一起匯入，也可長按曲庫中的歌曲附加歌詞。點選歌詞可跳到對應時間。
- 以自己的 HTTPS Navidrome 伺服器搜尋與串流，讀取封面和伺服器提供的同步歌詞。伺服器使用有效且受信任的 TLS 憑證。帳號資訊與密碼存於 iPhone 的鑰匙圈。
- 內建 30 秒「潮汐之間」示範音軌與歌詞，可離線試用。

0.1.0 採用原生歌詞清單；0.3.0 開始直接使用桌面版 Sonnet 引擎。0.3.1 內建 OpenCC 繁體字幕；0.3.4 加入繪光；其餘桌面動畫樣式與通用 Folium 插件系統尚未移植。

## 0.3.7：優先尋找有字幕軌的翻譯影片

搜尋合併 YouTube 的 CC 篩選和一般結果，優先顯示有翻譯標記的 CC 影片，並顯示上傳頻道。影片標題同時引用作品名與片尾曲名時，依曲名與演出者比對。YouTube 列出中文 CC 軌卻回傳空內容時，會重新取得公開播放器提供的字幕網址，診斷會記錄每條嘗試的字幕軌。未列出中文 CC 時才嘗試辨識畫面文字。音源配對可辨認不同平台上的宇多田光署名。雙人演唱影片與正式音軌有少量長度差時，仍會核對完整歌名及所有演出者。

## 0.3.6：歌單串流、翻譯影片字幕、整頁繪光

1. 點「YouTube」選擇歌單或「喜歡的影片」，Folia 會記住最後選擇。可播放整份、隨機、搜尋、重新排序、更名、加入本機歌曲。長按歌曲可安排下一首、移除、附加音檔。編輯只保存在 Folia，YouTube 原歌單維持唯讀。
2. 點歌先試可播放的本機檔與比對到的 Navidrome、網易雲、QQ 音樂音源，必要時試原 YouTube 影片公開音訊。以原生音訊播放，不開影片視窗。Spotify 可瀏覽曲庫，但未作為完整音源。
3. 長按 →「下載音樂」→ 確認，才會尋找可下載音檔。優先無損，其次比較可取得的音質資訊；其他來源都失敗再嘗試 YouTube。驗證檔案大小、時長與整段解碼才放入「檔案 → 我的 iPhone → Folia → YouTube Music」。受地區、登入、驗證或平台回覆限制的音源可能無法取得。
4. 播放頁「尋找歌詞」→「依目前歌曲找翻譯影片」，也可貼已有人工字幕的 YouTube 影片。先讀獨立字幕軌；字幕印在畫面上時會嘗試辨識公開影片，或讓你匯入已有的影片。檢查預覽再套用。無法證明與目前原詞對齊時，預覽會標示使用影片時間；可校正字幕時間。辨識不會自動翻譯。
5. 選「繪光」後，動畫與控制按鈕套用整頁樣式。歌詞按實際播放時鐘前進，緩衝、暫停和拖曳時不會繼續自行跑。原字幕會保留；繁體字幕設定可查看或複製文字診斷，JSON 可另行匯出。

測試夾具驗證本機音訊和介面流程；公開來源、Google 帳號、翻譯影片取得與實際手機效能仍須實機確認。Google 憑證僅供官方歌單與頻道資料 API，不會送給其他音源。

## 0.3.4：繪光、尋找歌詞與暫停修正

build 10 補上字幕運算頁的視窗生命週期與啟動確認、程序中斷後的自動恢復，以及設定版本檢查，避免舊的停用回覆蓋掉重新啟用。若暫時無法恢復，可在繁體字幕設定按「重新準備字幕」。

1. 播放頁上方可選「商籟／繪光／歌詞／封面」，本機與 YouTube 共用並保存選擇。繪光使用桌面 Lumiere 的程式編排、光束、煙霧、文字動態與轉場；目前沒有音訊頻譜輸入，光效不會宣稱與鼓點同步。
2. 點播放頁「尋找歌詞」（YouTube 在右上角「⋯」），即可重新尋找網易雲、QQ、YouTube 的既有中文字幕，也能搜尋 LRCLIB 的其他同步歌詞版本、查看來源或還原原字幕。設定頁不再另外放搜尋按鈕。
3. 首頁「設定 → 繁體字幕」保留內建模組的全部轉換與來源選項；尋找歌詞頁右上角齒輪也可開啟。模組仍是內建、可停用、不能刪除。
4. 設定中的「省電動畫」使用 30 fps 上限及較低解析度；一般模式上限 60 fps。系統低耗電模式也會採用省電動畫。這是渲染上限，不保證所有手機或複雜場景達到該幀率。
5. 暫停指令會直接暫停 WebKit 媒體，並帶版本號確認播放器回覆；舊播放回覆不再推進歌詞時鐘。暫停且進度不變時不重畫，補上歌詞與切歌會沿用同樣式的 WebGL 資源。原生進度通知由 20 Hz 降為 10 Hz，舞台以獨立時鐘補間；背景柔光降低更新頻率並去除額外模糊濾鏡。
6. 播放控制與主要按鈕增加按壓縮放、透明度和觸覺回饋，遵循「減少動態效果」。

**0.3.4 歷史行為（0.3.5 已由獨立音檔播放取代）**：當時採可見的官方 IFrame 播放器。暫停測試另使用僅限 Debug 的本機媒體夾具，不以平台驗證失敗冒充播放成功；正式 IPA 不含該測試入口。真實 YouTube 影片與字幕的可用性仍需手機確認。

## 0.3.3：平台搜尋修正

- 網易雲預設改用表單 cloud-search 入口，安裝者仍不必填 API 網址；正確保留歌名內的 `+`、`&` 與中文字。
- YouTube 搜尋加入網站本身的「字幕」篩選，再檢查人工中文軌，避免只靠「中字」標題浪費候選名額。字幕篩選本身不代表一定有中文或能下載。
- 官方頻道的中日文／英文藝名前後順序不同時，只在兩個明確藝名完全一致的情況下採用相同非拉丁藝名；不猜測漢字讀音。
- 診斷接收實際 App 版本，並在網易雲解析失敗時記錄搜尋／字幕階段、資料大小及 result／songs 的型別，不記錄原始回覆、歌詞或憑證。
- 保留原插件 1.1.6 的所有既有字幕處理設定與命令；平台登入、地區、驗證限制仍由平台決定，不繞過驗證或宣稱任何影片都能匯入。

## 0.3.2：內建繁體字幕與跨平台搜尋

1. 安裝新版後，進入首頁右上角「設定 → 繁體字幕」。播放畫面也有「繁體字幕設定」入口；YouTube 播放頁在右上角「⋯」。
2. 預設啟用離線簡轉繁、自動尋找中文字幕及載入失敗備援。可分開調整原文／和聲、中文譯文、臺灣／標準字形、日韓文字保護及標準／深入搜尋。
3. 想只保留離線簡轉繁，關閉「自動尋找中文字幕」與「字幕載入失敗時自動改用其他來源」。想顯示完整原字幕，關閉「啟用內建模組」。設定會保留至下次啟動；內建項目沒有刪除入口。
4. 用「重新尋找中文字幕」重試目前歌曲；「還原這首歌的原字幕」會撤銷自動補譯／備援並暫停這首歌的自動搜尋，簡轉繁仍依設定。手動重新尋找可解除暫停。
5. 「查看字幕來源與中文覆蓋率」顯示目前結果；「完整診斷報告」可捲動、選字、複製或儲存 JSON 至「檔案」。查看與匯出不會重新搜尋，報告只保存在記憶體。

轉換、歌曲版本核對、中文品質及分行比對、固定時間差校正、還原、搜尋上限與診斷使用原插件 **1.1.6** 的相同引擎與固定字典，沒有重寫成簡化字表。FIA 的和聲、逐字／音節、注音、其他語言譯文和分詞欄位通過原生橋接保留；商籟與原生歌詞清單共用轉換結果，原始檔案不變。

**預設字幕來源**：依序搜尋網易雲、QQ 音樂、YouTube，再檢查本機已附加歌詞、已連接的 Navidrome、LRCLIB。網易雲與 QQ 音樂讀取平台已提供的原詞與中文譯文，安裝者不必設定 API。YouTube 搜尋已有人工中文字幕的影片，並先檢查目前播放影片；只讀現有字幕軌，不使用 ASR 或機器翻譯。不同錄音仍須通過原插件的原詞／版本／時間對齊核對，保留目前歌曲的逐字動畫。

進入字幕設定，向下捲到「跨平台字幕來源」可分別開關三個平台，再按「重新尋找中文字幕」。設定與完整診斷會列出各平台候選數、讀取行數或失敗原因。選填的自訂網易雲 API 位於「進階」；一般使用留空即可。

**YouTube 限制**：影片標題寫「中字」不代表提供字幕軌。壓在畫面內的字幕無法直接轉為歌詞；無公開人工中文軌、要求登入／驗證、地區限制、空白字幕回覆時，會保留原字幕並記錄原因。YouTube Data API 的字幕下載要求影片編輯權限，因此 Google 曲庫登入並不能授權下載任意影片字幕；這裡讀取公開網頁可提供的字幕，不繞過驗證。公開頁面接口可能變更，無法保證每首都成功。詳見[功能與來源對照](SubtitleEngine/README.md)。

## 0.3.0：商籟與 App 內播放

- 播放頁預設使用真正的電腦版 Sonnet 引擎，包括文字拆分、構圖、鏡頭移動與轉場；不是原先只有捲動的歌詞清單。可切換「商籟／歌詞／封面」，按取景框進入沉浸模式。
- YouTube 歌單、喜歡影片的播放按鈕改為 Folia 內的官方播放器。也能在 YouTube 頁直接貼上單支 YouTube／YouTube Music 連結，無須先登入即可播放允許嵌入的公開影片。
- 播放器的實際時間驅動 Sonnet；處理暫停、緩衝、拖曳、舊頁面回應與切歌，切換本機播放時停止 YouTube，避免同時出聲。
- 依歌曲名稱、歌手與時長向 LRCLIB 自動匹配同步歌詞。不相符時不套用；可從播放選項手動搜尋版本或附加 LRC／FIA。手動附加的歌詞按影片 ID 保存在裝置上，來源標記為 LRCLIB 或手動附加。
- YouTube 官方影片區保持可見且至少 200 × 200；不提供分離音訊、隱藏影片或鎖定螢幕的 YouTube 背景播放。離開畫面、開啟歌詞選擇器或 App 切到背景時暫停。本機與 Navidrome 的背景音訊功能仍可使用。
- 部分影片、私人影片、年齡或區域限制內容無法嵌入；App 會顯示錯誤，不會自動跳去外部 App。
- 這不是 YouTube Music 完整客戶端；帳號曲庫範圍仍受官方 YouTube Data API 限制。移植的桌面原始碼、版本與建置方式見 [Visualizer](Visualizer/README.md)。

## 0.2.0 更新

- 歌詞換句時使用彈性捲動、位移與縮放，依距離調整模糊和透明度；目前歌詞帶有流動掃光。普通逐句 LRC 也能看到動畫，逐字著色仍依歌詞提供的時間資料。
- 播放背景使用持續移動的柔光。暫停、離開播放畫面或 App 進入背景後停止逐幀動畫，並遵循 iOS「減少動態效果」。
- 首頁增加 Spotify、YouTube 來源頁。使用系統瀏覽器登入，讀取歌單、收藏及分頁，點選歌曲會在原平台開啟。平台授權憑證存於鑰匙圈，可在帳號設定中移除。

### Spotify 首次設定

1. 在 [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) 建立自己的應用程式，選擇 iOS / Web API，Redirect URI 登記 `folia-spotify://callback`。
2. 開發模式的應用程式擁有者需有 Spotify Premium。將實際登入的 Spotify 帳號加入應用程式的測試使用者名單。
3. 在 Folia 的 Spotify 頁按「設定並登入」，填入 **Client ID**，按「登入並讀取曲庫」，在 Spotify 官方驗證視窗授權。
4. 可瀏覽帳號歌單、喜歡的歌曲，或開啟原平台。依 2026 年開發模式規則，只有自己擁有或協作歌單能讀取內容，其他歌單可能回覆 403。

### Google／YouTube 維護者統一設定

請閱讀 [Google／YouTube：維護者設定與發布教學](docs/Google-YouTube-maintainer.zh-TW.md)。維護者建立 iOS OAuth 用戶端後，在 GitHub 的 **Settings → Secrets and variables → Actions → Variables** 設定 `GOOGLE_IOS_CLIENT_ID` 與 `GOOGLE_IOS_BUNDLE_ID`，重新建置後發給使用者。兩者為公開應用程式識別資料，App 不內建 Client Secret 或任何使用者帳號憑證。

使用者在 Folia 的 YouTube 頁直接按「連接 Google 帳號」並授權即可。測試階段的登入帳號仍需由維護者加入 Google Cloud 測試使用者名單。

Google iOS 用戶端登記的 Bundle ID 必須與實際安裝版本一致；側載前的建置識別碼是獨立的 `FOLIA_BUILD_BUNDLE_ID`，預設保持專案原始值。側載工具若改寫它，Google 登入會顯示版本不相符；由每位安裝者各自重簽的 IPA 不保證能共用相同用戶端。正式分發需規劃維護者統一簽署與固定識別碼。

Spotify 仍使用原平台播放；YouTube 只同步歌單，配對的獨立音檔在 App 內播放並搭配 Folia 歌詞動畫。Google 入口讀取官方 YouTube API 提供的帳號歌單與喜歡影片，可取得範圍與 YouTube Music 完整曲庫可能不同。

Spotify 標誌使用其[官方設計資源](https://developer.spotify.com/documentation/design)，僅用於平台內容歸屬標示。

## 在 Mac 建置並裝到 iPhone

1. 使用 Xcode 16 或更新版本開啟 `ios/Folia.xcodeproj`。
2. 選 `Folia` target → **Signing & Capabilities**，啟用 **Automatically manage signing** 並選擇自己的 Team。若 Bundle Identifier 已被使用，改為自己的唯一識別碼。
3. 連接 iPhone，在 Xcode 選該 iPhone 為執行目的地。若手機提示，前往「設定 → 隱私權與安全性 → 開發者模式」完成設定。
4. 按 **Run**，安裝後點「潮汐之間」驗證播放。也可先選擇 iPhone 模擬器確認 App 啟動。

## 在 Windows 觸發 GitHub 建置

將 ZIP 內的 `ios/` 與 `.github/workflows/folia-ios.yml` 一起放進自己有寫入權限的 GitHub 儲存庫根目錄。用 Git 推送變更後，在該儲存庫的 **Actions → Folia native iOS** 看結果。若工作流程已在預設分支，也可用 **Run workflow** 手動執行。

工作流程會檢查歌詞及曲庫邏輯、編譯模擬器與 iPhone 版本，並在 iPhone 模擬器執行播放與平台設定介面測試，最後上傳 `Folia-iOS-unsigned.ipa`。該 IPA 必須用適用於裝置的憑證及佈建描述檔簽署後才能安裝。若用自己的 Mac 和 iPhone，直接從 Xcode 按 **Run** 即可由 Xcode 處理開發簽署。

## 驗證

從專案根目錄執行 `bash ios/Checks/run.sh`，需 Swift 6。這會驗證歌詞時間軸、曲庫回應與分頁、重複歌曲、OAuth 回呼驗證、範例歌詞、Xcode 專案引用和背景音訊宣告。GitHub Actions 在 macOS 上執行這些檢查、Apple SDK 編譯和模擬器介面測試，畫面截圖會存入 `Folia-iOS-UI-checks` 建置產物。

0.1.0 曾經過兩輪獨立程式碼審查，修正歌詞記憶體使用、佇列更新、匯入與重試問題。Google 統一設定的帳號連接仍需用維護者的真實 iOS Client ID 與授權帳號驗證；自動化檢查涵蓋回應格式和介面，不代表已完成真實帳號登入。實機動畫、電量消耗和平台資料範圍仍需在 iPhone 驗證。

在實機上可依序確認以下操作。

1. 播放示範音軌，拖曳進度，點選歌詞，確認畫面跟上。
2. 播放時鎖定螢幕，在鎖定畫面按暫停、播放，並測試用多首歌組成的佇列切歌。
3. 從「檔案」匯入同名的音檔和歌詞，重啟 App 後確認歌曲與歌詞仍可使用。
4. 連線自己的 Navidrome，搜尋並播放一首有同步歌詞的歌曲，確認封面、時間軸和進度拖曳。
